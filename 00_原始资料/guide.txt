             大模型技术创新赛

1.1 竞赛规则

  一、 赛题背景
  大模型技术创新赛是以人工智能前沿技术为核心驱动的综合性竞赛，聚焦大
模型技术的突破性应用与生态构建，旨在激发高校团队探索大模型在自然语言处
理、多模态交互、知识推理等领域的创新潜力。赛事通过开放真实场景数据集与
算力资源，鼓励参赛者攻克模型轻量化、推理效率优化、垂直领域适配等关键技
术难题，倡导构建可持续的 AI 创新生态。比赛不仅为技术人才提供展示与交流
平台，更致力于打通产学研用链条，加速大模型技术从实验室研究向产业赋能的
转化进程，助力数字经济时代智能化升级。
  为推动大模型技术在智能物流领域的创新应用，本赛题以仓储基地分拣及搬
运为主题，参赛选手需基于指定设备设计一套智能作业系统，结合大模型、计算
机视觉、导航、机械臂抓取技术，解决货物识别与导航、精准抓取与放置等核心
问题。本赛项旨在激发参赛选手的创新能力，推动智能物流技术与可持续发展的
融合。
  二、 比赛内容
  比赛使用仿真平台，结合大模型、ROS2 机器人操作系统、视觉技术等主流
技术，开发一套目标识别到作业执行的智能系统。
  比赛开始利用移动机器人规划最优路径到达目标区域，避开障碍物；基于大
模型和计算机视觉技术，识别仓储中的目标货物（如红色或蓝色包裹），并生成
位置信息；执行货物抓取、搬运与放置动作，将目标物拾取后放置于指定区域；
通过语言大模型用自然语言发布命令，设计可视化界面显示作业内容。参赛队伍
 需根据提供的仿真环境（Gazebo + ROS2），设计算法方案并实现功能。

1.2 竞赛分析

     为了让大家更深入的了解该赛事的竞赛核心，该小节从 Linux 系统简介，虚
拟机和 U 盘双系统使用, ROS2 机器人操作系统，Gazebo 仿真环境，Nav2 导航
系统，MoveIt2 机械臂控制，计算机视觉技术，语言大模型的应用，可视化工具
使用多个角度进行竞赛分析。
一、   Linux 系统简介
     Ubuntu 是 ROS2 的最佳开发环境，其开源特性和稳定性能为机器人开发提
供有力支持。需要学习 Linux 的基本操作， ROS 发行版与 Ubuntu 系统的紧密
关联，尽管 ROS2 对 Windows 等平台有一定支持，但 Ubuntu 仍是最优选择。
同时，需掌握 Linux 命令行操作，如 cd、pwd、mkdir、ls、gedit 等常用命令，
这些命令在搭建开发环境、编译代码、运行程序等过程中必不可少。
     二、 虚拟机和 U 盘双系统使用
  虚拟机为在 Windows 系统上运行 Ubuntu 系统提供了便捷方式，需学习虚
拟机的基本使用，包括 Linux 在虚拟机中的搭建与使用。重点掌握虚拟机网络
配置，了解 NAT、桥接、仅主机三种网卡类型的特点，根据需求选择合适的模式，
如桥接模式可实现虚拟机与外部网络的通信，确保 ROS 程序能正常与外部交互。
  U 盘双系统则通过启动盘在物理机上独立运行 Ubuntu，直接使用物理机硬
件，避免虚拟机性能损耗，适合对算力要求较高的场景。需掌握启动盘的使用、
BIOS 启动项设置，双系统切换。
     三、 ROS2 机器人操作系统
  ROS2 是整个系统的核心通信框架，是开展后续所有操作（包括 Gazebo 仿
真环境的使用、各模块间的交互等）的基础。需熟练掌握其话题（Topics）、服
务（Services）和动作（Actions）的使用。比如，通过话题控制机器人速度，
利用动作控制机械臂运动，调用服务实现夹爪对物体的抓取与释放。此外，还需
了解 ROS2 的节点管理、消息类型定义等知识，确保各个模块之间能够高效、稳
定地通信。
     四、 Gazebo 仿真环境
  比赛基于 Gazebo 仿真平台，而 Gazebo 的使用依赖于 ROS2 的支持，所有
的视觉识别、导航规划、机械臂控制等操作都需要在仿真环境中进行验证。通过
ros2 命令启动包含机械臂、底盘和传感器的仿真环境，能够在仿真环境中添加
障碍物、设置货物位置等。此外，还需了解仿真环境中传感器（雷达、相机等），
例如雷达的扫描范围和精度、相机等参数设置，以便更好地利用这些数据进行决
策。
     五、 Nav2 导航系统
  Nav2 是移动机器人实现自主导航的核心框架，其整合了感知、路径规划、
运动控制与定位等核心功能，能够支撑机器人在存在动态障碍、完成从起点到目
标点的自主移动。
   在应用层面，需掌握如何向 Nav2 系统发布目标点以触发导航任务，以及如
何通过设置初始位姿估计为机器人提供全局定位基准。同时，要学会通过订阅导
航过程中生成的路径规划数据，实时监控导航状态，确保机器人能够高效避开障
碍并精准抵达目标区域 。
   六、 机械臂控制和 MoveIt2
   在 Gazebo 仿真环境中，机械臂控制虽提供了基础的关节控制接口（如直接
发送关节角度指令）和关节状态反馈功能，但直接通过关节角度进行精细化作业
（如精准抓取特定位置的货物）存在显著难度。
   MoveIt2 用于机械臂运动规划与控制。其核心价值在于通过封装运动学算法
与路径优化逻辑，将复杂的机械臂控制转化为对末端执行器目标位姿的直接设定。
   通过 MoveIt2，可实现从 "目标货物抓取点" 到 "机械臂末端运动轨迹" 的
自动转换，无需手动计算关节角度，即可精准控制机械臂完成抓取，大幅降低机
械臂操作的复杂度
   七、 计算机视觉技术
   计算机视觉技术用于目标识别与定位，需学习图像处理基础知识，如使用
OpenCV 进行颜色阈值分割、轮廓检测，识别货物颜色和形状等。
   八、 语言大模型的应用
   语言大模型（LLM）在人机交互中的应用场景广泛且具有变革性，智能客服
与虚拟助手、车载与物联网交互等。
   在技术层面通常的方案有 NLP 解析、MCP 架构、Function Calling 等。从自
然语言提取关键信息再映射为类机器人指令，控制机器人完成任务。


   九、 可视化工具使用
   可视化工具（rqt、rviz、foxglove）用于监控机器人状态，需学习各工具
的功能和使用方法。如 rqt 监控节点和话题，rviz 展示机器人模型和传感器数
据，foxglove 通过 Rosbridge WebSocket protocol 实现数据可视化，支持自
定义布局整合暂时的信息。
1.3 竞赛实战指导

一、   Linux 系统简介
     时间回到 1991 年，一位热爱计算机的芬兰大学
生林纳斯，在熟悉了操作系统原理和 unix 系统后，
决定自己动手做一个，实践是检验真理的唯一标准，
说干就干，他参考已有的一些通用标准，重新设计了
一套操作系统内核，不仅可以实现多用户、多任务的
管理，还可以兼容 unix 原有的应用程序。最重要的
是，他把这套尚不成熟的操作系统分享到了互联网上，

并用自己的名字命名了这套系统，也就是 Linux。

     原本出于个人爱好的 Linux 系统通过互联网快速传播，更多爱好者看到
Linux 之后，也激发了乐于分享的热情，就把使用过程中的问题和修复方法做了
反馈。
     一石激起千层浪，越来越多人加入到了 Linux 维护的行列当中，一个原本功
能有限、bug 很多的操作系统，快速强大起来，伴随其中发扬光大的是开源精神。
     与 Windows 系统收费，或 MacOS 硬件绑定的模式不同，Linux 是一套免费并
且开放源代码的操作系统，任何人都可以使用或者提交反馈，这就吸引了大量的
开发者、爱好者，甚至很多企业，现在，每年对 Linux 系统提交的代码量已经成
为衡量一个大公司技术实力的重要指标之一。
     Linux 发展迅猛，已经成为了性能稳定的多用户操作系统，也是 ROS2 依赖
的重要底层系统。虽然 ROS2 目前也支持 Windows、MacOS，但对 Linux 系统的支
持最好。
     所以在使用 ROS2 之前，我们需要先安装 Linux，此时会出现另外一个概念
——发行版。
  什么叫发行版呢？准确来讲，我们提到的 Linux 应该叫做操作系统内核，并
没有可视化界面，发行版就是给这个内核加上华丽的外衣，把操作界面和各种应
用软件放到一起，打包成我们安装系统的镜像。




  所以一般情况下，我们常用到的 Linux 系统，都是各种各样的发行版，比如
Ubuntu、Fedora、RedHat 等等，每一个发行版都有其适用的场景，比如 RedHat
适合商业应用、CentOS 适合服务器、Ubuntu、Fedora 适合个人使用等，每一个
版本的界面不太一样，但核心都是 Linux，操作方法基本相同。
  Ubuntu 系统简介
  Ubuntu 诞生于 2004 年 10 月份，每六个月发布一个新版本，用户可以一直
免费升级使用。在软件开发领域，无论是互联网开发，还是人工智能开发，还是
机器人开发，Ubuntu 都占据绝对重要的位置。
  Ubuntu 的版本变动比较快，版本不同会影响上层应用的移植效果。版本的
编号如 Ubuntu22.04。22 代表 2022 年，04 表示 2022 年的 4 月份发布，除了 04
还可能会出现的是 10，就是 10 月份发布，所以从数字编号上就可以看出各个版
本发布的顺序。
     为了让更多开发者有一个稳定的系统环境，Ubuntu 每隔两年的 4 月份会发
布一个长期支持版，后缀会加 LTS，保证 5 年之内持续维护更新，比如 Ubuntu20.04
LTS，Ubuntu22.04 LTS，除此之外的版本都是普通版，只维护 18 个月。




     目前最新的长期支持版是 Ubuntu24.04 LTS,但是当前不论是 ROS2 还是
Gazebo，在 Ubuntu22.04 LTS 都会比 Ubuntu24.04 LTS 稳定一些。

虚拟机网络设置
  虚拟机网卡类型有三种，NAT、桥接、仅主机；默认一般是 NAT,如果需要让
虚拟机内部的 ros 程序可以和外部通信需要设置网卡为桥接模式。
  可以在编辑>虚拟网络编辑器>更改设置，选择桥接模式的虚拟网卡（一般是
VMnet0），选择对应的网卡，比如有线网卡。
                      （默认自动可能桥接失败，尤其是设
备有多个网卡时）




  之后在虚拟机设置>网络适配器>连接方式选择桥接模式。在虚拟机内部设置
静态 IP，和电脑在同一网段即可。
   三种模式的区别
  桥接模式 在这种模式下，VMWare 虚拟出来的操作系统就像是局域网中的一
台独立的主机，它可以访问网内任何一台机器。 在桥接模式下，你需要手工为
虚拟系统配置 IP 地址、子网掩码，而且还要和宿主机器处于同一网段，这样虚
拟系统才能和宿主机器进行通信。同时，由 于这个虚拟系统是局域网中的一个
独立的主机系统，那么就可以手工配置它的 TCP/IP 配置信息，以实现通过局域
网的网关或路由器访问互联网。
  主机模式 在 host-only 模式中，所有的虚拟系统是可以相互通信的，但虚
拟系统和真实的网络是被隔离开的。
   NAT 使用 NAT 模式，就是让虚拟系统借助 NAT(网络地址转换)功能，通过
宿主机器所在的网络来访问公网。也就是说，使用 NAT 模式可以实现在虚拟 系
统里访问互联网。NAT 模式下的虚拟系统的 TCP/IP 配置信息是由 VMnet8(NAT)
虚拟网络的 DHCP 服务器提供的，无法进行手工修改，因此虚拟系统也就无法和
本局域网中的其他真实主机进行通讯。采用 NAT 模式最大的优势是虚拟系统接入
互联网非常简单，你不需要进行任何其他的配置，只需要宿主机 器能访问互联
网即可。
U 盘双系统使用
  U 盘双系统则通过启动盘在物理机上独立运行 Ubuntu，直接使用物理机硬
件，避免虚拟机性能损耗，适合对算力要求较高的场景。
进入 U 盘系统
  1.进入 BIOS
  插入系统 U 盘，然后重启电脑。在开机过程中，根据屏幕提示按下相应的按
键（通常是 Del、F2、Esc 或 F10 等）进入 BIOS 设置界面。不同品牌和型号的主
板进入 BIOS 的按键可能不同，常见的按键包括：
  Del：大多数主板使用此键。
  F2：部分华硕（ASUS）和技嘉（Gigabyte）主板使用此键。
  Esc：部分惠普（HP）和联想（Lenovo）笔记本使用此键。
  F10：部分戴尔（Dell）和惠普（HP）笔记本使用此键。
  2. 设置启动项
  找到启动设置：进入 BIOS 后，找到“启动顺序”
                          （Boot Order）或“启动设
备”（Boot Device）选项。设置 U 盘为第一启动项：
  在启动顺序列表中，找到 U 盘设备（通常显示为“USB Drive”或类似名称）。
将 U 盘设置为第一启动项。通常可以通过上下箭头键选择设备，然后按“+”或
“-”键调整顺序，或者直接选择“设置为第一启动项”选项。




  3.启用 USB 启动功能
  检查 USB 启动功能：在 BIOS 设置中，找到“安全启动”（Secure Boot）或
“启动选项”（Boot Options）。
     如果“安全启动”已启用，建议先禁用它，因为某些 U 盘启动盘可能不支持
安全启动。
     确保“USB 启动”或“从 USB 设备启动”选项已启用。如果未启用，即使 U
盘插入，也可能无法从 U 盘启动。
     4. 保存设置并重启
     保存设置：完成上述设置后，按“F10”键（或 BIOS 界面中提示的保存键）
保存设置并退出 BIOS。
     重启电脑：电脑将自动重启，并尝试从 U 盘启动。如果 U 盘启动盘制作正确，
系统将从 U 盘加载启动界面。因 U 盘读写速度限制，加载过程大概黑屏 2~3 分钟。




三、   ROS2-机器人操作系统
简介
     ROS---一句话概括是用于构建机器人应用程序的软件开发工具包。ROS 是开
源的，它由一组软件库和若干工具组成。
     整个 ROS 生态可以包括通信（Plumbing）、工具（Tools）、功能（Capabilities）
与社区（Community）四大部分组成。
  通信-> 通信是整个 ROS 系统的核心实现，是 ROS 内置的一个消息传递系统.
在构建新的应用或使用与硬件交互的软件时，如何实现通信是首先要解决的问题，
为此 ROS 提供了专门的消息传递系统，它可以管理不同节点之间的通信细节，提
高开发者的工作效率。这套消息传递系统使用了“面向接口”的编程思想，可以
通过清晰规范的接口，将不同模块分离，从而也将故障隔离。使得 ROS 系统更易
于维护、扩展性更强且保证了程序的高复用性。接口规范可以由开发者自行定义。
同时为了方便使用，在 ROS 中也提供了许多标准的接口，这些标准接口有着广泛
应用，比如：将雷达或摄像头数据传输到可视化的用户界面或是传输到定位算法
模块，都会使用到标准接口。也提供了多种通信模型，比如发布订阅、请求响应、
请求反馈, 这些后面也会带大家详细了解。
  工具-> 构建机器人应用是比较有挑战性的。开发者除了会遇到一些传统的
软件开发问题之外，还需要通过传感器或执行器与物理世界进行异步交互。显而
易见的，良好的开发工具可以提高应用程序的开发效率，在 ROS 中就内置了节点
启动工具--launch、终端调试工具、可视化程序--RQT,Rviz、录制回放-- rosbag
等一系列工具。这些工具不光可以提高开发效率，还可以在发布产品时直接包含
在产品之中。
  功能集-> ROS 生态系统是机器人软件的聚宝盆。一个开源的应用商店，无
论开发者需要用于 GPS 的设备驱动程序、用于机器人控制器，还是用于移动机器
人的地图系统，ROS 都能满足你的需求。从驱动程序到算法，再到用户界面，ROS
都提供了相关实现，开发者只需专注于自身应用程序即可。
ROS 的目标是提供一站式的技术支持，降低构建机器人应用程序的门槛。ROS 希
望任何开发者都可以将自己的“创意”变为现实，而无需了解底层软件和硬件的

  ROS2 包（Package）的基本结构
  功能包是 ROS2 应用程序的核心，但是功能包不能直接构建，必须依赖于工
作空间，一个 ROS2 工作空间的目录结构如下：
 WorkSpace --- 自定义的工作空间。
 |--- build：存储中间文件的目录，该目录下会为每一个功能包创建一个单独子目录。
 |--- install：安装目录，该目录下会为每一个功能包创建一个单独子目录。
 |--- log：日志目录，用于存储日志文件。
 |--- src：用于存储功能包源码的目录。
   |-- C++功能包
      |-- package.xml：包信息，比如:包名、版本、作者、依赖项。
      |-- CMakeLists.txt：配置编译规则，比如源文件、依赖项、目标文件。
      |-- src：C++源文件目录。
      |-- include：头文件目录。
      |-- msg：消息接口文件目录。
      |-- srv：服务接口文件目录。
      |-- action：动作接口文件目录。
   |-- Python 功能包
      |-- package.xml：包信息，比如:包名、版本、作者、依赖项。
      |-- setup.py：与 C++功能包的 CMakeLists.txt 类似。
      |-- setup.cfg：功能包基本配置文件。
      |-- resource：资源目录。
      |-- test：存储测试相关文件。
      |-- 功能包同名目录：Python 源文件目录。



 另外，无论是 Python 功能包还是 C++功能包，都可以自定义一些配置文件相
关的目录。
   |-- C++或 Python 功能包
         |-- launch：存储 launch 文件。
         |-- rviz：存储 rviz2 配置相关文件。
         |-- urdf：存储机器人建模文件。
         |-- params：存储参数文件。
         |-- world：存储仿真环境相关文件。
         |-- map：存储导航所需地图文件。
         |-- ......

       了解了工作空间的概念和结果，接下来我们可以使用如下命令创建一个工作
空间
# 一个空的工作空间必须存在 src 目录才能被编译
mkdir -p ~/demo_ws/src
cd ~/demo_ws/
# 使用 colcon 编译

       创建功能包
       如何在 ROS2 中创建一个功能包呢？我们可以使用这个指令：
ros2 pkg create --build-type <build-type> <package_name> --node-name <node_name>

       ros2 命令中：
       pkg：表示功能包相关的功能；
       create：表示创建功能包；
       build-type：表示新创建的功能包是 C++还是 Python 的，如果使用 C++
        或者 C，那这里就跟 ament_cmake，如果使用 Python，就跟 ament_python；
       package_name：新建功能包的名字，功能包名称再工作空间中必须是唯一
        的。
       node-name:可选参数,在包中创建一个简单的 Hello World 类型的可执
        行文件。
       比如在终端中分别创建 C++和 Python 版本的功能包：
cd ~/demo_ws/src
ros2 pkg create --build-type ament_cmake pkg_c --node-name hello_ros   # C++
ros2 pkg create --build-type ament_python pkg_py --node-name hello_ros # Python

       编译功能包
       在创建好的功能包中，我们可以继续完成代码的编写，之后需要编译和配置
环境变量，才能正常运行：
cd ~/demo_ws
colcon build   # 编译工作空间所有功能包
# 也可以编译指定功能包
colcon build --packages-select pkg_c pkg_py

       功能包的结构
       功能包并不是普通的文件夹，那如何判断一个文件夹是否是功能包呢？我们
来分析下刚才新创建两个功能包的结构。
       C++功能包
       首先看下 C++类型的功能包，其中必然存在两个文件：package.xml 和
CMakerLists.txt。




       package.xml 文件的主要内容如下，包含功能包的版权描述，和各种依赖的
声明。




       CMakeLists.txt 文件是编译规则，C++代码需要编译才能运行，所以必须要
在该文件中设置如何编译，使用 CMake 语法。




  Python 功能包
  C++功能包需要将源码编译成可执行文件，但是 Python 语言是解析型的，不
需要编译，所以会有一些不同，但也会有这两个文件：package.xml 和 setup.py。




  package.xml 文件的主要内容和 C++版本功能包一样，包含功能包的版权描
述，和各种依赖的声明。




  setup.py 文件里边也包含一些版权信息，除此之外，还有“entry_points”
配置的程序入口，与 Cmake 中的 install 类似，会让 ros2 run 找到程序入口。

六、      机械臂控制和 MoveIt2
        MoveIt2 是 ROS2 中的一个集成开发平台，一个专注于机器人操作（尤其是
机械臂） 的开源运动规划框架。由多种用于操纵机械臂的功能包组成，包括：
运动规划、操作、控制接口、逆向运动学、3D 感知和碰撞检测等。MoveIt 简化
了复杂的机器人运动规划和应用开发工作。无论是学术研究还是工业应用，
MoveIt2 为开发者提供了一个高层次的功能封装，使得开发者可以更专注于机器
人应用逻辑本身，而不必深入底层算法细节。
     一般机械臂的关节都会提供位置控制、力控制或速度控制接口给我们使用。




     如 Gazebo 仿 真 的 这 个 六 轴 机 械 臂 提 供 了 /joint_trajectory 话 题 和
/follow_joint_trajectory 动作接口，可以控制六个关节的角度。假如我们可
以改变每一个关节的角度，那么就可以让机械臂的末端到达各种姿态。
     但随之而来的问题就来了，如何让机械臂末端以我们想要的速度、想要的轨

         实际应用中，关节控制通常用在主动控制，如遥控，或者机械臂只要特定几

         关节正解：[关节角度->末端位姿]，现有的关节角度推导末端执行器位姿
         关节逆解：[末端位姿->关节角度]，期望位姿推导关节角度
         如果已知目标物体的位置，可以通过以下流程实现控制机械臂末端移动到目
标物体位置。
         已知目标位姿》计算末端位姿》[当前关节角度+末端位姿]》关节逆解》目
标关节角度》电机控制
         实际的流程要更复杂，规划器、轨迹优化、关节限制、障碍、碰撞等；

#include <memory>
#include <rclcpp/rclcpp.hpp>
#include <moveit/move_group_interface/move_group_interface.h>


int main(int argc, char *argv[])
{
    // Initialize ROS and create the Node
    rclcpp::init(argc, argv);
    auto const node = std::make_shared<rclcpp::Node>(
         "hello_moveit",
         rclcpp::NodeOptions().automatically_declare_parameters_from_overrides(true));
    // Create a ROS logger
    auto const logger = rclcpp::get_logger("hello_moveit");
    // Create the MoveIt MoveGroup Interface
    using moveit::planning_interface::MoveGroupInterface;
    auto move_group_interface = MoveGroupInterface(node, "arm");
    // Set a target Pose
    geometry_msgs::msg::Pose target_pose;
    target_pose.orientation.w = 1.0;
    target_pose.position.x = 0.28;
    target_pose.position.y = -0.2;
    target_pose.position.z = 0.5;
    move_group_interface.setPoseTarget(target_pose);
    // Create a plan to that target pose
    auto const [success, plan] = [&move_group_interface]
    {
        moveit::planning_interface::MoveGroupInterface::Plan msg;
        auto const ok = static_cast<bool>(move_group_interface.plan(msg));
        return std::make_pair(ok, msg);
    }();
    // Execute the plan
    if (success)
    {
        move_group_interface.execute(plan);
    }
    else
    {
        RCLCPP_ERROR(logger, "Planing failed!");
    }
    // Shutdown ROS
    rclcpp::shutdown();
    return 0;
}

七、      计算机视觉技术
   机器视觉， 就是用计算机来模拟人的视觉功能，但这并不仅仅是人眼的简
单延伸，更重要的是像人脑一样，可以从客观事物的图像中提取信息，进行处理
并加以理解，最终用于实际检测、控制等场景。




   机器视觉凭借速度、精度和可重复性等优势，非常适合对结构化场景进行定
量测量。一般来讲，典型的机器视觉系统可以分为如图所示的三个部分：图像采
集、图像分析和控制输出。
   选择合适的相机是机器视觉系统设计的重要环节，通常相机可以获取的信息
除了 RGB 图像，还可以获取如深度、能量等信息，不仅直接决定了采集图像的质
量和速度，同时也与整个系统的运行模式相关。
   图像处理系统接收到相机传来的数字图像之后，通过各种软件算法进行图像
特征提取、特征分析，最后进行判断。这是各种视觉算法研究最为集中的部分，
如基于 opencv 实现颜色过滤、轮廓检测，到基于深度学习的目标检测算法。从
传统的模式识别算法，到当前热门的各种机器学习方法，都是为了更好的让机器
理解环境。
   视觉识别的结果最终要和机器人的某些行为绑定，也就是第三个部分——输
出，包含 I/O 接口、运动控制、可视化显示等。当图像处理系统完成图像分析后，
将识别的结果输出。比如视觉识别到了抓取目标的位置，通过 IO 口控制夹爪完
成抓取和放置、将识别的信息可视化等。
Opencv 视觉识别

     图像数据

     在 ROS 中图像消息通常是通过 Image 和 CompressedImage 消息进行定义的。
  数据结构中首先是消息头，包含序号、时间戳、坐标系这三项内容。
  接下来是一幅图像的相关数据。比如纵向和横向的分辨率，两者做一个乘法
之后的结果，就表示这幅图像中有多少像素点，每一个像素点的描述方式，在这
个 encoding 中定义，最为常用的是 RGB 格式，也就是一个像素点的颜色，由红、
绿、蓝三原色组成。
  下边是图像数据的大小端模式，step 表示一行图像数据的字节数量，方便
之后在数据中寻址使用。
  data 是一个二维数组，依次存储每个像素点的 RGB 信息，RGB 分别是 3 个 8
位的数据表示，大家可以算一下，如果是一幅 1920*1080 分辨率的高清图片，这
个数组将会保存 3*1920*1080 个字节的数据，也就是 6MB 左右的大小，假设摄像
头每秒采集 20 幅图像，还要乘以 20，上百兆每秒的数据量着实不小，会占用大
量的带宽资源。




  所以在日常的数据传输中，尤其是通过无线网络传输时，所有涉及到多设备
无线传输时更为常用的方式是使用压缩后的图像。

  之后在回调函数 self.listener_callback 中通过 opencv 实现图像处理的逻
辑；OpenCV 中针对图像数据有专门的定义，和 ROS 中的图像消息不同，为了可
以兼容 OpenCV，需要使用 CvBridge 的功能包，它的任务很明确，就是将 ROS
中的图像消息转换为 OpenCV 中的图像数据结构，或者反过来，将 OpenCV 中的图

  CvBridge 就像是一座桥，打通了 ROS 与 OpenCV 之间的数据通道
  修改 hello_cv.py




  之后在 object_detect 中通过目标物体的特征实现检测逻辑；最直接的特征
就是颜色，此外还有像素面积、轮廓检测、四边形检测、霍夫圆检测等




  通常实现对特定颜色物体的检测需要把色彩模型从 RGB 转为 HSV。平时常见
的图片一般都是 RGB 模型。但是这种方式不太符合人的直观感受，比如随便给你
一个颜色，很少有人可以说出这个颜色对应的三原色比例。所以产生了第二种更
加符合人描述和解释的方式，叫做 HSV 模型。也就是每个像素点使用色调、饱和
度、亮度进行描述。
     HSV 模型由 Smith 在 1978 年创建，也称为倒锥形模型。
     其中 H 表示色调，用模型的圆形边界描述，是一个 0 度到 360 度的角度值，
在这个锥体模型上，以红色为起点，值为 0 度，逆时针方向计算，度数逐渐增大，
直到 360 度又回到了红色。其中绿色，是 120 度，蓝色是 240 度，对应到三原色
的话，刚好还是红绿蓝均分了色调 360 度的取值范围。
     S 是饱和度，用模型的水平轴描述，表示颜色接近光谱色的程度，取值范围
是 0%到 100%，值越大，颜色约饱和，也就是看上去越艳丽。
     V 表示亮度，用模型的垂直轴描述，也就是颜色的明亮程度，取值范围也是
0%到 100%，如果是 0%的话，就是最暗的黑色，如果是 100%的，就是最亮的白色。




     通过 opencv 可以很方便获取图片像素的 HSV,H[0-180],S[0-255],V[0-255]

hsv = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)
print("HSV:", hsv[y, x])

八、   语言大模型的应用
     语言大模型（LLM）在人机交互中的应用场景广泛且具有变革性，智能客服
与虚拟助手、车载与物联网交互等。
     在技术层面通常的方案有 NLP 解析、MCP 架构、Function Calling 等。NLP
解析 适用于简单指令转换，快但泛化能力弱。如输入："左边第二个盒子拿给我
" → NLP 模型 → 解析为 {"direction": "left", "index": 2, "object":
"box"} → 映射为机器人指令 robot.move(dir=left,index=2,obj=box);从自
然语言提取关键信息再映射为类机器人指令，控制机器人完成任务。
llama.cpp
     lama.cpp 是一个轻量级、高性能的 C/C++ 库，用于在常规硬件上高效运行
大型语言模型（LLMs）。它最初是 Meta 的 LLaMA 模型的纯 C/C++ 实现，但已
经发展成为一个全面的支持数十种流行 LLMs 的框架，具有显著的效率。
     可以将 llama.cpp 视为本地运行 AI 模型的瑞士军刀——它允许你在自己
的硬件上运行强大的语言模型，而无需云服务或庞大的基础设施。
     关键特性
     纯 C/C++ 实现，依赖最小
     llama.cpp 的 核 心 优 势 在 于 其 精 简 的 实 现 ， 不 依 赖 于 像 PyTorch 或
TensorFlow 这样的大型 AI 框架。这种“裸金属”方法意味着：
     更小的占用空间 - 可在资源有限的设备上运行
     更广泛的兼容性 - 跨操作系统和硬件工作
     更易于集成 - 可嵌入各种应用程序

    Foxglove Studio 是一个跨平台机器人数据可视化和分析的开源工具。支持

    Rosbridge

    Robot Web Tools 为 ROS 构建基于 Web 的机器人应用程序的开源库和工
具。 为非 ROS 程序提供了 API 实现到 ROS 的功能如 Node.js，JavaScript。
    rosbridge 为 ROS 提供了一个 JSON 接口，允许任何客户端发送 JSON 来
发布或订阅 ROS 主题、调用 ROS 服务等。rosbridge 支持多种传输层，包括
WebSockets 和 TCP。
   rosbridge_suite 是一个 ROS 元包 ，包含所有 rosbridge 包。
   可以使用 sudo apt install ros-$ROS_DISTRO-rosbridge-suite 命令安装。
   当启动 ros2 launch rosbridge_server rosbridge_websocket_launch.xml
命令后，所有的 ros 数据都会通过 WebSockets 转发。它把 ROS 话题/服务/参
数转译成 JSON → WebSocket → 任何客户端。
   rosbridge 客 户 端 是 使 用 其 JSON API 与 rosbridge 通 信 的 程 序 。
Rosbridge 客户包括 JavaScript API、 Java API、Rust API，通过 WebSockets
与 rosbridge 通信。
   Foxglove Studio 把 rosbridge 当作数据源之一，基于 WebSockets 协议实
现 3D、Map、Image、Plot、Log、Raw Message、Parameters 等多种数据的可视
