## 一、先纠正一个常见误解

> **公开（public）≠ 可写。**

| | public 仓库 | private 仓库 |
|---|---|---|
| 陌生人能**看**代码 | ✅ 能 | ❌ 不能 |
| 陌生人能**改**代码 | ❌ **不能** | ❌ 不能 |
| 被加为**协作者**的人 | ✅ 能推能拉 | ✅ 能推能拉 |

**所以现在队友只能 `git clone` 看代码，还不能往上推。**要让他们能推，有两条路。

---

## 二、两条协作路线（选一条）

### 路线 A：加协作者（推荐给 2~3 人固定小队）

**你要做的**：把队友的 GitHub 用户名给我，我一条命令加进去；或者你自己执行：

```bash
cd /home/robo/llm_comp
./06_脚本/13_添加队友到仓库.sh ghp_你的token 队友用户名1 队友用户名2
```

**队友要做的**：

1. 收到 GitHub 邀请邮件 → 点里面的 **View invitation → Accept**
   （或到 https://github.com/notifications 接受）
2. 接受后就能直接推：

```bash
git clone https://github.com/linzhi42506-collab/llm-competition.git
cd llm-competition
# ...改代码...
git add -A && git commit -m "我改了什么"
git push
```

> 队友第一次 push 时 GitHub 会要密码——**这里要填 Personal Access Token，不是账号密码**。
> 让队友也去 https://github.com/settings/tokens 生成一个（勾 `repo` 权限）。

**优点**：简单，一个仓库大家一起改。
**缺点**：谁都能直接改 main，容易互相覆盖。

---

### 路线 B：Fork + Pull Request（更规范，不怕互相覆盖）

队友**不需要任何权限**，public 仓库就能用：

1. 队友打开仓库页 → 右上角点 **Fork** → 代码复制到他自己的账号下
2. 他克隆**自己那份**改：

```bash
git clone https://github.com/队友用户名/llm-competition.git
# 改代码
git add -A && git commit -m "我改了什么"
git push
```

3. 回到**你的仓库**页面 → 会自动出现 **Compare & pull request** 按钮 → 点它提交 PR
4. **你会收到通知**，能看到他改了哪些行，点 **Merge** 合并

**优点**：改动必须经你确认才进主线，不会互相覆盖，GitHub 一定有通知。
**缺点**：多两步操作。

## 三、你怎么知道队友更新了？（重点）

我已经帮你把仓库**订阅成"所有活动"**了。除此之外：

| 队友的操作 | 你会不会收到通知 | 怎么看到 |
|-----------|-----------------|---------|
| **提 Pull Request**（路线 B） | ✅ **一定有**（站内 + 邮箱） | 仓库页 Pull requests 标签 |
| **开 Issue** | ✅ 一定有 | 仓库页 Issues 标签 |
| **直接 push**（路线 A） | ✅ 已订阅，会通知 | 仓库页 **Commits** 列表 |
| 提交评论 | ✅ 一定会 | 对应 PR/Issue 里 |

### 手动查看有没有更新

```bash
cd /home/robo/llm_comp

# 看远程有没有新提交
git fetch origin
git log --oneline HEAD..origin/main        # 有输出 = 队友推了新东西

# 看具体谁改了什么
git log origin/main --oneline --graph -10
git diff HEAD origin/main --stat

# 把队友的改动拉下来
git pull
```

### 在网页上看

- **全部提交**：https://github.com/linzhi42506-collab/llm-competition/commits/main
- **谁改了多少**：仓库页 → Insights → Contributors
- **某个文件的历史**：打开文件 → 右上角 History

## 四、⚠️ 多人同时改会冲突，怎么避免

两个人同时改**同一个文件**，后推的人会被 GitHub 拒绝：

```
! [rejected] main -> main (non-fast-forward)
```

**正确做法**：改代码前先拉、推之前再拉一次

```bash
git pull --rebase        # 先同步队友的改动
git add -A && git commit -m "..."
git pull --rebase        # 再拉一次（防止刚才有人推了）
git push
```

**更省事的团队约定**（建议跟队友说好）：

- 每人负责**不同文件/不同节点**，尽量别改同一个文件
  （比如：A 改 `task_manager.py`、B 改 `object_detector.py`、C 改文档）
- 配置类文件（`competition.yaml`、`nav2_competition.yaml`）改动前先在群里说一声
- 每次改完立刻推，别攒一堆
