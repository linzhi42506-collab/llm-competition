## 1. 作品概述

本作品面向"仓储基地分拣及搬运"赛题，基于 ROS2 Humble + Gazebo 仿真平台，
构建了一套「**大模型语义解析 → 视觉目标识别 → 自主导航避障 → 机械臂抓取放置 →
可视化状态反馈**」的端到端智能作业系统。

系统以自然语言形式接收随机生成的数学应用题及其"计算结果—颜色—区域"映射规则，
由大语言模型完成**解题 + 结构化指令生成**，输出形如 `[red,4,A;blue,1,C]` 的
机器可解析指令；随后由任务调度状态机驱动移动机器人依次完成 5 个目标货物的
识别、抓取、搬运与放置，并将任务信息、导航路径、作业进度实时发布到可视化面板。

## 3. 关键技术实现

### 3.1 大模型任务解析（评分项 2，10 分）

**问题**：题目随机生成，且需要同时完成"解应用题"和"按映射规则转换"两件事，
输出还必须能被程序稳定解析。

**方案**：三段式容错解析管线。

1. **云端大模型主通路**。用严格的 system prompt 约束模型只输出一行固定格式：
   `x=<整数>,y=<整数>,plan=[颜色,数量,区域;...]`，温度设为 0.1 保证稳定性。
   兼容 DeepSeek、智谱 AI、火山引擎、通义千问等任意 OpenAI 兼容接口，
   切换服务商只需改一行 YAML 配置。
2. **本地大模型备份通路**。集成 llama.cpp 的 `llama-server`（OpenAI 兼容），
   在无网络环境下降级使用。
3. **规则求解器兜底**。这是本作品针对比赛可靠性做的关键设计：
   - 用正则抽取"每个衣柜 N 件"的容量约束；
   - 分句统计 T 恤/裤子总需求量，并按 `ceil(总量 / 容量)` 求 x、y；
   - 用题目规律 `x + y = 5`、`x,y ≥ 1` 做一致性校验与修正；
   - 解析映射规则中的颜色对应、阈值分区（"数量大于等于 3 的去 A 区"）与
     抓取顺序关键词（"先/然后/最后"），生成最终计划。

   **实测**：本地 0.5B 小模型对本题型会算错（输出 x=1,y=1），规则兜底仍能
   稳定输出正确答案 `[red,4,A;blue,1,C]`，保证该评分项不因模型/网络问题丢分。

### 3.2 视觉目标识别（货物识别）

- 订阅 RGB-D 相机的彩色图与深度图，转 HSV 空间后对红、蓝两色做双区间阈值分割
  （红色跨越 H=0 需要两段区间），再经形态学开运算去噪；
- 对每个连通域求轮廓面积与质心，按面积阈值过滤噪声；
- 以质心为中心取 7×7 深度块取中值作为深度（中值滤波抗噪），
  结合相机内参反投影为相机坐标系三维点，再经 TF 变换到 `map` 坐标系；
- 识别结果以 JSON 与 MarkerArray 两种形式发布，既供调度层使用，也直接显示在面板上。

同时保留 Gazebo 真值（`/gazebo/model_states`）与预标定坐标表两条备份通路，
三者可按参数切换，保证现场稳定性。

### 3.3 自主导航与动态避障（评分项 5，10 分）

- 使用 Nav2（`nav2_bringup`）的 AMCL 定位 + 全局/局部代价地图 + 路径规划，
  通过 `nav2_simple_commander` 的 `goToPose` 以代码方式下发目标点，
  并在导航过程中订阅反馈实时显示"剩余距离"；
- 目标点自动生成为"货物/放置区前方 `approach_distance` 米、朝向目标"的位姿，
  使机械臂处于最佳作业距离；
- **动态障碍物**：通过 Gazebo 的 `set_entity_state` 服务在 10 Hz 下周期性修改
  障碍物模型位姿，使障碍物沿指定线段往复运动，形成真实的可移动障碍，
  迫使 Nav2 局部规划器实时重规划绕行。
  障碍物航点被刻意布置在机器人"起点→货物→放置区"的必经路线附近，
  以满足规则中"障碍物需位于路线附近，否则视为无效障碍"的要求。

### 3.4 机械臂抓取与放置（评分项 3、4，各 20 分）

- 通过 `/arm_controller/follow_joint_trajectory` 与
  `/gripper_controller/follow_joint_trajectory` 两个 `FollowJointTrajectory`
  动作接口，以关节空间轨迹点的方式驱动 6 轴机械臂与夹爪；
- 设计 `home → pre_grasp → grasp → carry → place → home` 六段式标准动作序列，
  参数化写入 YAML，便于现场快速标定；
- 货物与末端执行器的固连通过 LinkAttacher 的 `/ATTACHLINK`、`/DETACHLINK`
  服务实现（`model1=six_arm, link1=link6`，`model2=<red|blue>_cube_<n>, link2=link`），
  避免依赖复杂的接触摩擦参数，抓取成功率高、可复现。

### 3.5 任务调度状态机（评分项 6 的进度来源）

```
空闲 → 解析等待 → [对每个货物]
     前往资源点 → 识别资源 → 机械臂抓取 → 吸附 → 移动到放置区
     → 机械臂放置 → 释放 → 完成一轮任务 → (下一个货物) → 任务完成
```

- 把 `[red,4,A;blue,1,C]` 展开为 5 个具体 Job，每个 Job 绑定一个货物实例
  （如 `red_cube_1`）与目标区域坐标；
- 每次状态迁移都向 `/competition/task_status` 发布中文状态与进度（`已完成 n/5`），
  直接对应评分项 6 的"路径、工作进度、机械臂抓取状态、每一轮任务完成情况"；
- 单步异常不影响整体：某个货物失败自动跳过并继续下一个，保证 5 分钟内拿到尽可能多的分；
- 内置 `dry_run` 模式：不驱动真实动作，仅推进状态机，用于赛前彩排面板显示。

### 3.6 可视化状态反馈（评分项 6）

- 通过 `rosbridge_websocket`（9090 端口）把 ROS2 话题转成 WebSocket JSON，
  供 Foxglove / coStudio 订阅；
- `panel_node` 把四类必需信息聚合成**单个 JSON 话题** `/competition/panel`
  与纯文本话题 `/competition/panel_text`，面板只需一个 Raw Message 控件即可
  完整展示，大幅降低现场布局出错风险；
- 同时发布 `nav_msgs/Path` 形式的规划路径与实际轨迹，供 3D 面板绘图。

## 4. 创新点

1. **三段式容错任务解析**：云端大模型 → 本地大模型 → 规则求解器，
   把"模型算错/网络中断"这一最大不确定性从评分项 2 中消除。
2. **结构化输出强约束**：用固定格式 + 正则校验 + `x+y=5` 不变量校验，
   把自然语言的开放输出收敛成可验证的机器指令。
3. **干跑（dry_run）彩排机制**：把"算法正确性"与"机械臂标定"解耦，
   可独立验证状态反馈与面板显示。
4. **单 JSON 汇总面板**：把多控件布局风险降为单控件，提升现场可靠性。
5. **参数化场景与坐标记录工具**：场景改造后一键导出坐标，无需现场视觉标定。

## 5. 场景设计（评分项 7，10 分）

| 评分要点 | 本作品设计 |
|----------|------------|
| 货物位置彼此距离 ≥ 2 m | 5 个目标货物分散布置，两两间距 ≥ 2 m，并各自置于独立支撑台上 |
| 放置区至少隔一面墙 | A/B/C 三区布置在由隔墙分开的独立区域，机器人必须绕行 |
| ≥ 2 个有效障碍物 | 2 个动态障碍物沿"起点—货物—放置区"路线往复运动 |

障碍物轨迹、货物与区域坐标全部参数化在 `config/competition.yaml` 中。

## 7. 总结与展望

本作品把大语言模型的语义理解能力与 ROS2 机器人系统的确定性执行能力结合，
并通过多层兜底设计解决了"大模型不确定性"与"比赛限时一次性"之间的矛盾。
后续可进一步引入视觉大模型（VLM）直接完成"图像→抓取点"的端到端推理，
以及用强化学习优化动态障碍环境下的局部规划策略。
